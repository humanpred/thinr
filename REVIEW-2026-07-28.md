   `thinImage`, case-insensitive, every file, `.git` excluded): the **only**
   hit anywhere in the repository is `NEWS.md:49`: *"Removed `thinImage()`.
   Use `thin()` (Zhang-Suen is the default method)."* — a historical note
   about the removal, not a live claim.
3. **The false claim was not just corrected, it was removed at the source**:
   `git log --all -S"drop-in replacement" -- DESCRIPTION` and `--oneline -- '**/*thinImage*'`
   show two commits already on `origin/main`: `f338bc8 Correct EBImage::thinImage()
   references: no such function exists`, followed later by `0be0e5d Remove
   thinImage(): superseded by thin()`. The confusingly-named function itself
   (which invited the false equivalence in the first place) no longer exists
   — `R/thin_image.R` and `man/thinImage.Rd` are both absent from the current
   tree (confirmed: today's `R/` has exactly 5 files —
   `distance_transform.R`, `medial_axis.R`, `RcppExports.R`, `thin.R`,
   `thinr-package.R` — none of them `thin_image.R`).
4. **Current framing is correct and precise everywhere I found an EBImage
   reference** (`DESCRIPTION`, `README.md`, `CLAUDE.md`, `ARCHITECTURE.md`,
   `R/thinr-package.R`, `vignettes/correctness-properties.Rmd`): every one
   says `thinr` *complements* `EBImage` (which "provides binary morphology...
   but no thinning operator") rather than replacing any of its functions.
   `CLAUDE.md` line 7 states it explicitly: *"EBImage provides binary
   morphology but no thinning operator, so thinr complements it rather than

## Silent-degradation hunt (item C) — summary

- **Defaults nobody overrides:** `thin(max_iter = 1000L)` is never overridden
  by the one ecosystem caller (`figureextractraster::extract_raster()`) —
  checked, and this is **not** a footgun default: it is a documented safety
  ceiling ("Real binary images of typical sizes converge well under 50
  passes; the limit is a safety bound against pathological inputs"), not a
  tuning knob whose wrong value silently degrades output the way
  `n_colours = 2L` did elsewhere in the ecosystem. No finding.
- **`tryCatch`/`try()` swallowing errors:** none in `R/` or `src/`.
- **NA / degenerate input:** rejected loudly and uniformly at the
  `as_binary_matrix()` boundary for every storage mode and every one of the
  three public entry points (F016, re-verified).
- **Empty vs. broken:** `thin()`/`medial_axis()`/`distance_transform()` on an
  all-background image correctly return all-zero/all-background output
  (tested); a malformed input (wrong dimensions, wrong storage mode, `NA`) is
  rejected with a classed, informative `stop()`, never silently coerced.
- **Magic numbers:** none found undocumented in R or C++; the K3M lookup
  tables and OPTA/Hilditch boolean expressions are transcriptions from named,
  cited papers (verified where checkable — see the EBImage section above for
  the standard of verification applied).
